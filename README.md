# Knowledge Agent · 个人知识中心
把日常 AI 对话整理成有来源、可审核、可持续更新的 Markdown 笔记。

![Knowledge Agent：从对话、审核到可复用笔记](docs/assets/cover.svg)

**本地优先 · 逐次确认保存 · 可追溯来源**

个人项目 / AI 辅助开发 / 可运行原型。[English](README.en.md) · [演示步骤](docs/demo.md) · [架构与取舍](docs/architecture.md) · [验证记录](docs/verification.md)

## 为什么做这个项目

有价值的判断散落在 Codex、ChatGPT 的多次讨论里。复制一份聊天摘要很容易；难的是后续讨论变化时，知道哪篇笔记需要更新、依据是什么，以及怎样保留自己改过的内容。

Knowledge Agent 将**来源、提案、审核和写入**分开：助手提炼内容，程序核对版本与证据，你决定是否保存。它适合需要追溯依据、逐步维护知识的个人工作流；临时总结直接在聊天中完成更方便。

## 三步体验

需要 **Node.js 24+、npm 和浏览器**。从本仓库下载 ZIP 并解压，或克隆后，进入项目目录运行：

```bash
npm ci --ignore-scripts
npm run demo:product
```

打开终端 JSON 中的 `home` 地址，然后：

1. **草稿审查**：点击“原文保真与增量整理”进入详情，展开“查看来源”。
2. **查看保存预览**：核对目标与正文，勾选确认并保存。
3. **来源与运行 → 来源配置与手动读取**：点击“演示：新增一段对话”，返回草稿审查，查看同一篇笔记的更新差异；保存后可从保存记录恢复。

**演示全为合成内容，不需要 API Key，不调用模型，不读取真实聊天或现有笔记。** 写入只落在新建的私有临时目录；`Ctrl+C` 停止服务。安装依赖需要网络，演示运行不需要外部服务。`npm start` 也启动此演示。

## 能体验到什么

| 场景 | 已实现行为 |
| --- | --- |
| 一段讨论来自哪里 | 保留消息版本、逐字来源与实际读取范围；部分历史不会冒充完整历史 |
| 后续讨论补充了结论 | 更新持续主题；旧来源或旧预览失效后，需要重新核对 |
| 笔记已有人工补充 | 受管理区块之外保留原字节；冲突时拒绝覆盖 |
| 重复点击或中断 | 持久化记录和幂等保存；结果不明时不自动重跑 |
| 想撤销一次更新 | 核对写后哈希再恢复；后续人工编辑会阻止恢复 |
| 助手提出行动建议 | 只有人工采纳才进入正式行动，不把建议当成承诺 |

## 工程设计

```mermaid
flowchart LR
  A[授权范围的对话] --> B[来源与版本账本]
  B --> C[助手提炼主题]
  C --> D[证据与版本校验]
  D --> E[人工审核与差异预览]
  E --> F[确认写入 Markdown]
  F --> G[写入记录与受控恢复]
```

Node.js 原生 HTTP 服务、ES modules、浏览器 JavaScript、私有文件存储。模型负责语义提案；确定性程序负责身份、权限、冲突和写入。源码导览与设计取舍见 [架构说明](docs/architecture.md)。

## 验证与当前边界

```bash
npm test
```

测试使用合成输入、临时笔记库与模拟 Provider。覆盖来源失效、人工反馈保护、重复保存、恢复和 HTTP 权限等边界；**测试数量不等于内容准确率**。[本次验证环境与结果](docs/verification.md)

- 这是可运行的个人原型，尚未证明长期语义质量、持续使用收益或生产稳定性。
- Codex 读取需显式配置范围；ChatGPT 依赖授权工具读取。本机服务不独立登录账号，也不保证完整历史或附件采集。
- 主演示使用固定合成结果；真实语义整理需要助手参与。无人值守模型执行与周期同步未作为已交付能力展示。
- 可选笔记检索有集成代码，但不是默认演示依赖；本次未重验外部检索引擎。
- 已在 macOS / Node 24 验证本地安装与演示；Linux CI 配置已提供，执行结果须以实际运行记录为准。Windows 暂未验证。
