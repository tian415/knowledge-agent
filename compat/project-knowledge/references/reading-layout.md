# 让知识库便于阅读

首页回答三个问题：项目是什么、目前怎样、接下来做什么。主题页补足判断依据，不用相同字数限制删掉重要内容。

一个小项目先用平铺结构：`00-首页.md`、`01-产品取舍.md`、`02-系统结构.md`，有实际记录再建 `记录/`。不要给单篇笔记套一层“产品思考/工程理解”目录；候选不足一页时放在相关主题末尾。

同一项目可能有多个产品、终端和聊天。整理前建立“项目 → 产品/终端 → 模块”的关系，并列出相关会话。逐条处理后续纠正：被推翻的名称和范围只能进入变更记录，不能继续当作当前事实。用户明确纠正优先于 AI 旧方案；“继续”不证明所有细节已确认。

覆盖应检查：目标与约束、范围变化、选项与理由、模块与调用、数据权威与权限、失败处理、分工与依赖、验收与未知。没有材料的项目不补造答案。摘要可以短，但不能只留术语而删掉为什么这样选。

正文用明确措辞区分“已表达的要求”“建议”“未核验实现”。每节状态和原文定位保存在折叠来源里，不为每个段落增加提示框。已有好内容应合并保留。

图优先表达关系：系统边界、请求流程、数据流、协作依赖。图上注明“设计建议”或“现状”，不要把设计图画成已部署事实。本地 PNG 放项目的 `图示/`，通过 section.images 引用；图和文字应传达同一结论。截图只在确有理解价值、已检查内容且适合保存时使用。

Obsidian 文件夹默认可能排在笔记前，`00-` 只控制同类排序。可将首页加入书签并置顶；可选 CSS 片段 `obsidian-reading.css` 将编号首页置顶，并只为带 `cssclasses: [pk-note]` 的笔记调整阅读样式。旧笔记无需批量套用。使用前备份配置，在“外观 → CSS 代码片段”启用，并检查实际界面。

调整既有路径时：先备份完整知识库和状态 → 核对管理区未被手改 → 在副本移动文件、同步配置与状态中的路径、更新链接 → 检查链接和导入去重 → 再对原库执行同一迁移。稳定 ID 不必跟显示名称改变；不可通过删除状态绕过冲突保护。核心尚未提供通用项目重命名命令。

表格中的 Wiki 链接别名分隔符要转义为 `\|`，或者使用普通 Markdown 链接。交付前在 Obsidian 阅读视图检查表格、图片、折叠来源与首页排序，不能只做文本检查。文件树存在按需渲染，展开大量目录时 CSS 排序不能保证全局置顶。首页优先使用原生书签并放第一项；CSS 只作编号主题的辅助排序，升级后复核。

参考：[Obsidian 书签](https://help.obsidian.md/Plugins/Bookmarks)支持手动排序；[CSS 片段](https://help.obsidian.md/Extending+Obsidian/CSS+snippets)通过外观设置启用。
