# 架构与工程取舍

目标是将多次讨论沉淀成可追溯且能更新的知识，保留用户对事实、承诺和文件变更的决定权。

## 数据路径

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `src/capture/codex.mjs` / `chatgpt-thread.mjs` | 来源适配与读取范围 | 只读授权范围；partial 缺失不代表删除 |
| `src/capture/store.mjs` / `processing.mjs` | 来源版本、领取与结果账本 | 领取先持久化；结果不明不自动重跑 |
| `src/capture/topics.mjs` | 跨讨论的持续主题 | 新来源使旧结果待复核；保留人工反馈 |
| `src/capture/topic-publish.mjs` | 主题到具体写入计划 | 来源、主题、预览都绑定当前版本 |
| `src/apply/knowledge.mjs` | 文件预览、保存、恢复 | 单写锁、目标哈希、明确确认、读回 |
| `src/apply/managed-topic.mjs` | 受管理区块 | 区块外原字节保留；普通笔记需显式审阅合并 |
| `src/app/product.mjs` / `web/capture/` | 统一 HTTP 工作台 | 回环监听、同源检查、会话令牌 |
| `src/workspace/` | 人工行动与状态 | 建议只有采纳后才成为正式行动 |

演示路径是 `scripts/demo-knowledge.mjs` → `src/capture/demo.mjs` → 同一组 Store、Publisher、Writer 和网页接口。合成的是来源与语义结果，保存与冲突检查走实际实现。

## 为什么这样设计

**语义与执行分离。** 模型可以解释和提炼，但不能决定一个过期预览是否还能覆盖文件。确定性程序检查身份、路径、哈希和权限，语义质量另行审核。

**增量维护主题。** 单聊天摘要适合回顾；持续主题适合复用。主题引用消息版本，后续讨论变化会触发复核，避免把新的依据偷偷套在旧结论上。

**文件存储与本地 HTTP。** 个人使用优先选择容易检查和备份的文件，配合锁、原子落盘和读回。没有多用户写入或大规模分布式场景，不为展示增加数据库和队列；高并发和海量历史尚未验证。

**人工笔记优先。** 受管理内容之外保持原字节。普通笔记的合并必须绑定审阅时目标哈希，不以自动重写规避冲突。

**未知仍是未知。** 不把字节换算成实测 token，不把模拟用量算成真实消耗，不把逐字证据通过算成语义结论正确。

## 可追踪的回归入口

- `tests/capture/product-flow.test.mjs`：HTTP 保存、更新、恢复、来源失效和人工修改。
- `tests/apply/knowledge.test.mjs`：Writer 幂等、预览摘要、路径、权限与部分失败。
- `tests/capture/topics.test.mjs`：主题版本和人工反馈。
- `tests/capture/adapters.test.mjs`：原文身份、部分历史与注入隔离。
- `tests/capture/usage.test.mjs`：实测、未知与模拟用量。

## 展示版本的整理边界

此发行目录是现有本地实现的独立快照，未携带原 Git 历史、私人资料、真实运行状态或本机 Registry。保留产品源码与确定性回归。历史付费实验和迁移脚本未发布；两个旧实验模块只保留回归需要的纯导出兼容层。

为首次安装修复了普通 `.git` 目录处理、未配置 Vault 的路径诊断和系统临时目录兼容。原工作树未被此展示整理覆盖。完整开发史仍保留在原本地仓库，展示仓库的首次快照不伪装成历史开发记录。
